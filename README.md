# AI-SDLC — Self-Improving AI Software Development Lifecycle

[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

A reusable AI-assisted software development lifecycle (SDLC) toolkit. It extracts the AI-development
methodology from the [MetaTrader AutoTrading System](https://github.com/schmouli/MetaTrader) into a
standalone repo that combines five components with no trading-related code:

| Component | Purpose | Code |
|---|---|---|
| **Spec-Kit** | Structured, constitution-gated feature workflow: specify → clarify → plan → tasks → implement | [`.specify/`](.specify/), [`.github/skills/`](.github/skills/) |
| **EGM (Elephant-Goldfish Model)** | Zero-context adversarial document review | [`egm/`](egm/) |
| **Code Knowledge Graph** | Structural graph of the repo, two-step retrieval, review digest | [`src/kg/`](src/kg/) |
| **SkillBox** | Telemetry → learnings → overlays with human-approved activation | [`src/skillbox/`](src/skillbox/) |
| **AI-SDLC Telemetry + Dashboard** | Hook/round capture; lifecycle map; SDLC measurement pane | [`scripts/generate_lifecycle_map.py`](scripts/generate_lifecycle_map.py), [`scripts/generate_sdlc_pane.py`](scripts/generate_sdlc_pane.py) |
| **Installer** | Layer any component set into an existing repo, or use this repo as a template | [`install.py`](install.py) |

> **Advisory-only principle:** every component that renders a verdict is advisory. Gates can prompt
> you, but no automated output blocks implementation. Only human-run approval commands mutate state
> (SkillBox overlay activation).

## Repository layout

```text
.specify/            Spec-kit harness: constitution, templates, scripts, workflows, wiring manifest
.github/skills/      Skill files (base SKILL.md for each speckit skill) — SkillBox composes over them
egm/                 Installed EGM assets: skills/, agents/, personas/ (docs + resources), docs/
src/kg/              Code Knowledge Graph package (parser, builder, retrieval, digest, evaluation)
src/skillbox/        SkillBox package (telemetry, learnings, overlays, review, compose, inject, ...)
scripts/             CLI entry points and verifiers (knowledge graph, wiring, skillbox, dashboards)
tests/               pytest suites per component (wiring, skillbox, kg)
docs/                Generated lifecycle map + component docs (wiring flow, overview, protocol)
dashboards/          SDLC dashboard HTML — generated by scripts/generate_sdlc_pane.py
data/                Tracked measurement series (context budgets); append-only
config/              Minimal env configs (skillbox on/off per env) for config.settings
.specify/contracts/  Wiring manifest / verifier / capture protocol contracts (from spec-kit)
```

Excluded by design per the extraction scope: `specs/<feature>/` directories, the MetaTrader trading
loop (`src/trading`, `src/communication`, EA files), ML training, and any live trading data.

## 1. Spec-Kit — constitution-gated feature workflow

**Location:** [`.specify/`](.specify/)
**Entry:** the global speckit CLI plus [`.github/skills/speckit-*`](.github/skills/)

Spec-Kit structures AI feature work into reviewable artifacts instead of ad-hoc prompts:

- [`.specify/memory/constitution.md`](.specify/memory/constitution.md) — non-negotiable principles
  (advisory-only findings, fail-soft telemetry, timezone contract, write-scope rules).
- [`.specify/templates/`](.specify/templates/) — canonical shape of each stage's output
  (`spec.md`, `plan.md`, `tasks.md`, checklist).
- [`.specify/scripts/powershell/`](.specify/scripts/powershell/) — support scripts for stage execution.
- [`.specify/workflows/`](.specify/workflows/) + [`.specify/integrations/`](.specify/integrations/) —
  workflow registry and harness manifests.

The five lifecycle stages:

1. **Specify** — natural-language description → `specs/NNN-feature/spec.md`.
2. **Clarify** — targeted questions; resolve into the spec.
3. **Plan** — technical design; choices recorded under the constitution.
4. **Tasks** — dependency-ordered, actionable task list with acceptance criteria.
5. **Implement** — execute tasks; verification conventions apply.

Each stage is a *skill*: a `SKILL.md` the AI harness loads. The base skill content is never modified —
SkillBox layers approved refinements on top (see §4).

Optional EGM hooks are declared in [`.specify/extensions.yml`](.specify/extensions.yml) — every one
(optional + disabled by default) or enabled; see §2 wiring.

## 2. EGM — Elephant-Goldfish Model (zero-context adversarial review)

**Location:** [`egm/`](egm/) (user-level install shipped in-repo), wired via [`.specify/extensions.yml`](.specify/extensions.yml)
**Skills:** `egm-review`, `egm-review-loop`, `egm-drift-report`, `egm-resolve`, `egm-bootstrap`, `egm-brainstorm`, `egm-draft`
**Agents:** [9 agent definitions](egm/agents/) plus [personas](egm/personas/agents/) in EGM upstream format

EGM reviews documents, not diffs: each reviewer runs with **zero conversation context** to avoid
confirmation bias. Reviewers are read-only, always advisory-only: findings never gate anything.

Wiring rules live in [.specify/wiring-manifest.yml](.specify/wiring-manifest.yml):

- **Review profiles** pin rosters and the **fan-out cap (≤5 Goldfish subagents per round)**:
  `SPEC` (4), `READINESS` (3), `TASKS` (3), `CONSISTENCY (3)`, `DRIFT` (0).
- **Consult matrix** defines which reviewers read the bounded KG digest (max 8 KB) before reviewing.
- **Token budgets** cap every artifact (digest 8 KB, inline excerpts 4 KB, etc.).

Typical stage hooks (all optional in extensions.yml):

| Stage | Command | Profile |
|---|---|---|
| after_specify | `egm.review.loop` | SPEC |
| after_plan | `egm-review` | READINESS |
| after_tasks | `egm.review.loop` | TASKS |
| after_analyze | `egm.review.loop` | CONSISTENCY |
| after_implement | `egm-drift-report` | DRIFT |

The 6-lens `egm-brainstorm` swarm is included as a manual command: it exceeds the fan-out cap and is
not wired as a hook.

### Install for use in a target repo

Copy `egm/` into your user-level extension dirs (adjust per harness):

```text
egm/skills/*  →  ~/.copilot/skills/
egm/agents/*  →  ~/.copilot/agents/
```

Or point the manifest's `egm_dependency` block at the in-repo copies:

```yaml
egm_dependency:
  skills_root: egm/skills        # repo-relative is sufficient for the verifier
  agents_root: egm/agents
  personas_root: egm/personas/agents
```

## 3. Code Knowledge Graph — structural map of the codebase

**Location:** [`src/kg/`](src/kg/)
**CLI:** [`scripts/run_knowledge_graph.py`](scripts/run_knowledge_graph.py)
**Doc:** [docs/AI_SDLC_WIRING_FLOW.md](docs/AI_SDLC_WIRING_FLOW.md)

**What it does.** A parser walks the repo's Python source and builds a directed graph of file nodes
(`f:<path>`), symbol nodes (`s:<path>#<qualified>`), and three edge types: `import`, calls`,
`coedit` (weighted by shared commits, capped at 5). The snapshot persists to
`output/kg/graph_snapshot.json` with an update-state file; the graph is regenerable (never
hand-edited).

**How to retrieve.** Deterministic two-step pipeline ([`src/kg/retrieval.py`](src/kg/retrieval.py)):

1. **Anchor** — lexical similarity between the query and every node's display text; the best matches
   become anchors.
2. **Expand** from anchors with **multi-hop BFS + PageRank** over a hybrid score
   `0.7 × PageRank + 0.3 × similarity` with per-hop decay.

```powershell
.\.venv\Scripts\python.exe scripts\run_knowledge_graph.py retrieve --query "adaptive threshold" --format json --top-k 8
```

**Review digest.** [`.specify/wiring-manifest.yml`](.specify/wiring-manifest.yml) caps the digest at
8 KB. It renders the top-25 files by PageRank with their top import partners, the top-10 co-edit
pairs, and a freshness label (`fresh`/`stale` vs HEAD). EGM reviewers with a `digest` consult entry
read the digest instead of the full snapshot — bounded context for zero-context reviewers.

**Commands.**

```powershell
python scripts/run_knowledge_graph.py build --full          # initial build (~1 min / 400+ files)
python scripts/run_knowledge_graph.py update                # incremental update after commits
python scripts/run_knowledge_graph.py report                # stats + freshness
python scripts/run_knowledge_graph.py retrieve --query "…"  # two-step retrieval
python scripts/run_knowledge_graph.py digest                # render review digest
python scripts/run_knowledge_graph.py verify                # schema/invariant self-check
python scripts/verify_knowledge_graph.py                    # data-model invariants (PASS/FAIL)
```

**Auto-updates.** [`scripts/hooks/post-commit`](scripts/hooks/post-commit) is a git post-commit hook
that runs `update` after every commit. Install with:

```powershell
Copy-Item scripts\hooks\post-commit .git\hooks\post-commit
```

Fail-soft guarantee: graph failures never block commits; writes are limited to `output/kg/` and
`logs/kg_builder.log`.

## 4. SkillBox — self-learning overlay system with a human approval gate

**Location:** [`src/skillbox/`](src/skillbox/)
**State:** `.skillbox/` (JSONL + SQLite; fully rebuildable from raw JSONL)
**Runtime status:** `python -m src.skillbox status`

SkillBox closes the loop between *observed agent behavior* and *skill guidance*:

```text
skills run (telemetry recorded) → patterns extracted (learnings) →
overlay proposed (staged PENDING) → human review approves →
overlay composes into future skill executions (+ digest refresh)
```

### Telemetry

Every skill activation records events (`skill_started`, `skill_completed`, `failure_event`,
`validation_result`, `command_result`, `composition_performed`, …) with session ids (`SBX-…`),
America/New_York ISO timestamps, sanitized payloads (credential-shaped keys redacted, file contents
omitted, strings capped at 400 chars), and deduplication hashes. Storage: append-only JSONL
(`.skillbox/telemetry/raw/YYYYMMDD.jsonl`) with a rebuildable SQLite index.

### Learnings

A deterministic aggregation engine ([`src/skillbox/learning.py`](src/skillbox/learning.py)) over the
telemetry window (default 90 days): outcome-rate patterns per (skill, event, category), cohort
contrasts, decision-reason clustering. Patterns reaching an evidence bar (frequency + consistency)
become `overlay-eligible`; evidence decay retires them (history preserved). No LLM involvement —
re-runs on unchanged data are byte-identical.

### Overlays and the approval gate

Overlays are collections of versioned markdown guidance (e.g. `testing/engineering-best-practices`),
append-only lineage at `.skillbox/overlays/<collection>/<slug>/versions/`. New versions always stage
as **pending**. Activation **only** through:

```powershell
python -m src.skillbox review approve testing/engineering-best-practices v02 --operator <you> --reason "…"
```

- Operator identity is recorded (env `SKILLBOX_OPERATOR` or `--operator`); missing identity is a loud error.
- Every decision appends a **hash-chained** audit record (`.skillbox/telemetry/review_decisions.json`)
  and the lineage index updates atomically (`active`, superseding the prior active version).
- `reject`/`rollback`/`re-activate` handle the full lifecycle. Pending versions **never** compose.
- Fail-safe: if the audit chain is unreadable, the resolver falls back to the last
  audit-verifiable approved version (or nothing) — an unapproved version is never returned.

The scheduler ([`scripts/skillbox_scheduler.py`](scripts/skillbox_scheduler.py)) runs reindex,
inference, MLflow push, learnings, overlay staging, and digest refresh on a loop. It reports
"NEVER_APPROVES" at startup — approvals are outside its capabilities by design.

### Composition & IDE injection

- **Per-skill composition** ([`src/skillbox/compose.py`](src/skillbox/compose.py)):
  base `SKILL.md` bytes verbatim + approved, collection-matched overlays appended under a divider.
  Pending/rejected versions never compose (spec SC-014).
- **IDE injection** ([`src/skillbox/inject.py`](src/skillbox/inject.py)): refreshes a marked block in
  `.github/copilot-instructions.md`; the block carries every approved overlay as bullet points
  (with approval provenance) — read by the AI harness at the start of every session. Content
  fingerprinting keeps refreshes idempotent.

The repo ships the **seed overlay** `testing/engineering-best-practices@v01` (active, approval
recorded), demonstrating the full lineage: seed → pending → active.

## 5. AI-SDLC Telemetry & Dashboard — measurement and visibility

**Location:** [`scripts/record_hook_acceptance.py`](scripts/record_hook_acceptance.py),
[`scripts/generate_lifecycle_map.py`](scripts/generate_lifecycle_map.py), [`scripts/generate_sdlc_pane.py`](scripts/generate_sdlc_pane.py)
**Capture flag:** `system.skillbox.wiring_capture_enabled` in the active env config

This component measures the AI-SDLC itself:

- **Hook acceptance ledger**: `.skillbox/wiring/hook_ledger.json` — every optional EGM gate records an
  accepted/skipped decision with operator + feature-dir via
  [`scripts/record_hook_acceptance.py`](scripts/record_hook_acceptance.py) (atomic, locked writes).
- **Round summaries**: EGM review rounds optionally drop `round-*.json` summaries into
  `logs/egm_rounds/`; a wiring sweep ([`src/skillbox/sweep.py`](src/skillbox/sweep.py)) records them
  as `egm_review_round` telemetry events with retention pruning.
- **Lifecycle map**: [`scripts/generate_lifecycle_map.py`](scripts/generate_lifecycle_map.py) renders
  [docs/AI_SDLC_LIFECYCLE_MAP.md](docs/AI_SDLC_LIFECYCLE_MAP.md) byte-idempotently from the two
  normative sources (extensions.yml + wiring-manifest.yml); `--check` mode exits non-zero when the
  map is hand-edited or stale.
- **SDLC dashboard**: [`.specify/contracts/verifier-contract.md`](.specify/contracts/verifier-contract.md)
  is the canonical predicate list; [`scripts/generate_sdlc_pane.py`](scripts/generate_sdlc_pane.py)
  renders it over collected measurements into
  [dashboards/sdlc_dashboard.html](dashboards/sdlc_dashboard.html) (written only when content
  changes). Advisory-only: "banner" findings are data, not failures. Storage is UTC; display is
  America/New_York. A series file (`data/context_budget_series.jsonl`) tracks context-budget trends
  over time.

All payloads pass a deny-pattern check for code/credentials leakage
([tests/wiring/test_content_exclusion.py](tests/wiring/test_content_exclusion.py)); the capture
schema is pinned in [.specify/contracts/capture-contract.md](.specify/contracts/capture-contract.md).

## Wiring verification — the end-to-end self-check

[`scripts/verify_wiring.py`](scripts/verify_wiring.py) validates the whole wiring declaratively in
two modes:

```powershell
python scripts/verify_wiring.py                        # live: full checks (D4/D8/D9/D12/A1 live-only)
python scripts/verify_wiring.py --sandbox <dir>        # fault-injection mode for tests
```

- **Defect codes** (`D1..D15`) for broken wiring: unparseable manifest, roster mismatch, hook-ceiling
  violation, lifecycle-map divergence, snapshot missing/stale, marker-region drift, etc.
- **Advisory labels** (`A1..A11`) for environmental observations (missing user-level EGM, stale digest):
  informational, never failures.

Run after every wiring change; expected exit code 0 with zero defects.


instrumentation is in place; until then the capture advisories stay suppressed.

## Design invariants worth preserving

1. **Constitution over convenience** — quick fixes never override `.specify/memory/constitution.md`.
2. **Approval-only activation** — SkillBox overlay activation is exclusively the human `review` path
   (FR-034); automation never approves.
3. **Fail-soft telemetry** — observability failures never break workflows (degradation codes
   `DEGRADE_*`).
4. **Advisory-only findings** — EGM and dashboard findings are signals, not gates.
5. **Write-scope discipline** — skillbox writes only `.skillbox/` + `logs/skillbox_*.log`; KG writes
   only `output/kg/` + `logs/kg_builder.log`.
6. **EST/EDT for state** — persisted timestamps use America/New_York; UTC only for wire formats.
7. **Source of truth** — declarative manifest + audit files win over derived artifacts; regenerable
   artifacts (lifecycle map, digest, snapshot) are never hand-edited.

## Deploying the toolkit into other repositories

Two supported paths, both self-contained (no user-level installation required —
the `egm/` tree ships in-repo and the wiring manifest points at repo-relative paths).

### Path 1 — template repository (greenfield)

Mark this repo as a **Template repository** (GitHub: Settings → *Template repository*
checkbox). Any user then clicks **Use this template** and receives the full layout
as a new repo, then runs the bootstrap below. Nothing in the layout is
machine-specific: `config/environments/` defaults are inert, the KG snapshot is
gitignored (regenerated by the first commit hook), and runtime telemetry starts
empty.

### Path 2 — `install.py` (brownfield: layer into an existing repo)

```powershell
# from a checkout of ai-sdlc
python install.py --target C:\path\to\their-repo              # everything
python install.py --target C:\path\to\their-repo --dry-run    # preview the plan
python install.py --target C:\path\to\their-repo --components kg,skillbox
```

What the installer does:

- copies only component-owned paths (idempotent safety: existing target files
  cause a refusal — pass `--force` to overwrite component-owned paths);
- never copies `specs/` feature folders or volatile runtime state (telemetry,
  learnings, reports, KG snapshots) — the target starts clean;
- rewrites `.specify/wiring-manifest.yml` `egm_dependency` to the in-repo
  `egm/` tree;
- seeds `config/environments/{development,production,testing}.json` when the
  target has none (SkillBox inert by default outside production);
- seeds a starter `.github/copilot-instructions.md` **only when the target has
  none** — an existing file is never touched;
- prints the bootstrap commands below.

Component ids and their contents: `spec-kit` (`.specify/` harness), `egm`
(skills/agents/personas), `kg` (graph engine + CLI + hook), `skillbox`
(runtime + curated overlay lineage), `telemetry` (hook acceptance + lifecycle
map + SDLC pane + wiring tests). The config layer (`config/settings.py`,
`src/log_config`) and `verify_wiring.py` always install.

### Bootstrap after either path (run inside the target repo)

```powershell
python -m venv .venv ; .\.venv\Scripts\pip install -r requirements.txt
Copy-Item scripts\hooks\post-commit .git\hooks\post-commit     # KG auto-stamp
.\.venv\Scripts\python -m src.skillbox registry reindex
.\.venv\Scripts\python scripts\run_knowledge_graph.py build --full
.\.venv\Scripts\python scripts\run_knowledge_graph.py digest
.\.venv\Scripts\python -m src.skillbox inject refresh
.\.venv\Scripts\python scripts\generate_lifecycle_map.py
.\.venv\Scripts\python scripts\verify_wiring.py               # expected: PASS
```

### Customize after install

- `README.md` — replace this toolkit's origin story with your repo's.
- `.specify/memory/constitution.md` — your project's principles (keep the
  advisory-only + fail-soft structure; edit the content).
- `config/environments/*.json` — switch SkillBox on/off per environment.
- Optional: set the manifest `wiring_adopted_at` stamp **only** together with
  `wiring_capture_enabled: true` when you adopt hook instrumentation.
